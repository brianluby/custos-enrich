# Security policy

## Reporting a vulnerability

This project does not yet have a public repository or private vulnerability-
reporting channel. Do not publish a release until this paragraph is replaced
with a working private advisory URL or monitored security email address.

Once that channel is listed, do not open a public issue for a suspected
vulnerability. Include affected versions, impact, reproduction steps, and any
suggested mitigation in the private report.

The maintainers will acknowledge a complete report, assess impact, and
coordinate disclosure and a release when needed.

## Scope

Security reports may include request construction, response validation,
resource-exhaustion risks, TLS configuration, dependency vulnerabilities, or
cases where malformed provider data can be mistaken for trustworthy
prioritization evidence.
